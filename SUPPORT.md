# Getting help

## Look first

Most questions are answered already, and these answer faster than a person can:

- [The documentation](https://docs.humanfia.ai/humanize/): a quickstart, then a guide for each
  task.
- [Troubleshooting](https://docs.humanfia.ai/humanize/user/troubleshooting): paste the message
  you got and find what to do about it.
- `hmz --help`, and `--help` after any command.
- [The issues](https://github.com/humanfia/humanize/issues?q=is%3Aissue), open and closed:
  someone may have asked before.

## Then ask

| You have | Open |
| --- | --- |
| a question the docs did not answer | a [question](https://github.com/humanfia/humanize/issues/new?template=question.yml) |
| something that does not work | a [bug report](https://github.com/humanfia/humanize/issues/new?template=bug_report.yml) |
| something you wish it did | a [feature request](https://github.com/humanfia/humanize/issues/new?template=feature_request.yml) |
| a page that is wrong, missing or unclear | a [docs issue](https://github.com/humanfia/humanize/issues/new?template=docs.yml) |
| a vulnerability | nothing public: follow [SECURITY.md](SECURITY.md) |

## What to expect

humanize is maintained by a few people, as well as they can. There is no paid support and no
promised response time. Only the latest release and `main` are supported, so
[upgrade](https://docs.humanfia.ai/humanize/user/installation#upgrade) first and check the
problem is still there.

Some questions are for someone else:

- signing in to a coding agent CLI, its billing, or its models: the CLI's vendor;
- a flow that is not built into humanize: the repository the flow comes from.
